## 最初の試作を見る

[Open-First-Room.cmd](Open-First-Room.cmd) で Blender 5.3 を起動します。起動時は机まわりの撮影視点です。テンキー 0 でカメラ表示を切り替えます。[描画画像](runs/20261117-105408-853-13920/Room-First-Look.png) · [スプラットPLY](runs/20261117-105408-853-13920/room.ply) · [測定結果](runs/20261117-105408-853-13920/result.json)

IMG_9785.MOV（約15秒）と IMG_9786.MOV（約140秒）から198フレームを抜きました。最大のまとまりは68フレームで、入口側とベッド側の一部は別々に復元されました。最大のまとまりを長辺1080 px・3,000ステップで学習し、14,499個のスプラットを保存しました。部屋全体を自由に見回すには撮り足しが必要です。試作の座標と縮尺は撮影からの推定です。家のモデルに重ねる際は実測寸法と基準点で合わせます。

## 撮り足す場所

- 入口・収納扉、机、ベッドを結ぶ横向きの4K動画を優先します。1×で、隣り合う家具や窓枠を同時に入れながら、撮る場所を少しずつ横へ移します。
- 同じ場所を腰の高さでもう一度通り、床と家具の接地を映します。上は窓枠・扉の上枠と天井の境目が一緒に映るようにします。室内照明やカーテンの状態をそろえると、前の映像と対応させやすくなります。
- 写真を足すなら、動画でぶれた箇所を少し違う角度から2〜3枚。少し引いた写真も含め、どの場所か分かるようにします。

カメラの位置と向きは、複数画像に写った共通点からCOLMAPが推定します。今回のMOVには表示の回転や位置情報のタグがありました。学習にはフレーム画像と画像から推定したカメラ情報を使っています。写真の場合、EXIFの焦点距離は推定の助けになります。[COLMAPの撮影ガイド](https://colmap.github.io/tutorial.html)

## 新しい素材で生成する

1. 同じ部屋の MOV、MP4、HEIC、HEIF、JPEG、PNG を D:\vibe\house-gaussian-splat\input に入れます。
2. [Train-Room.cmd](Train-Room.cmd) を開き、学習画像の解像度（長辺px）、動画の抽出fps、画像1枚あたりの平均ステップ数、ガウシアンの上限点数、学習方式の順に入力します。空欄でEnterを押すと原寸、5 fps、平均20ステップ、400万点、高速版Brushになります。学習方式の `2` でFaster-GS、`3` で高速版Faster-GSを選べます。FPSは `2.5` のような小数も指定できます。上限には `400万` や `4000000` と入力できます。登録1,393枚で平均20なら合計27,860ステップです。
3. [Open-Blender-Splats.cmd](Open-Blender-Splats.cmd) で、直近に生成が完了したPLYを読み込んだBlender 5.3を開きます。テンキー0でカメラ表示を切り替えます。

Wi-Fi撮影の保存フォルダを [Train-Room.cmd](Train-Room.cmd) にドラッグすると直接使えます。同じ部屋の撮影フォルダを複数使うときは、フォルダごと `input` の直下にコピーして通常どおり起動します。PNGと `frames.jsonl` は同じフォルダに置き、画像の名前を保ちます。ログの撮影順や向きは、カメラ推定前の画像照合の候補選びに使います。[Wi-Fi撮影の手順](wifi_capture/README.md#学習に使う)

解像度は長辺の上限です。4K（UHD、3840×2160 px）は `3840`、フルHD（1920×1080 px）は `1920`、元の解像度は `0` を入力します。ガウシアンの実数は学習に応じて増え、指定した上限まで達しない場合があります。カメラ位置を求めるときは長辺1,280 pxを使います。HEICとJPEGはデコードした画素を可逆圧縮のPNGにします。原寸用の動画フレームはカメラ位置が登録されたコマを元動画から再抽出し、その画素サイズに焦点距離と画像座標を換算してからレンズ補正します。

### PLYを起点に学習する

写真・動画と同じ `input` フォルダの直下にPLYを置き、[Train-Room.cmd](Train-Room.cmd) を起動します。通常の点群PLYなら頂点からガウシアンを作り、標準の非圧縮3DGS PLYなら位置・色・大きさ・向き・不透明度を初期値として引き継ぎます。学習方式はBrush、Faster-GS、高速版Faster-GSから選べます。上限点数はPLYの頂点数以上に設定します。複数のPLYがある場合は使いたいファイルを `init.ply` にするか、PowerShellで `-InitPly` にパスを指定します。

学習には対象の写真・動画とカメラ位置が必要です。`runs` に元の実行結果と学習データが残っている `room.ply` は、PLYだけを入れたフォルダを [Train-Room.cmd](Train-Room.cmd) にドラッグして再学習できます。外部のPLYを保存済みの画像で学習する場合は、PLYだけを入れたフォルダを `-InputFolder` に、画像とカメラを保存した実行名を `-ReuseRun` に渡します。外部PLYは学習用COLMAP座標と縮尺を合わせます。このプロジェクトの向き補正済みPLYは元の `alignment.json` で学習座標に戻します。元の実行結果を移動した場合はPLYと同じフォルダにその `alignment.json` を置きます。

### 過去のカメラ位置を使う

各実行でファイル名とSHA-256を記録します。同じ素材とfpsで完成済みのカメラ推定があれば自動で選びます。同じ解像度の学習データがあれば、レンズ補正済みの画像も使います。既存素材をすべて含んで撮り足した場合は、照合データベースをコピーし、追加画像を照合して、既存のカメラ位置を起点に登録します。既存素材を差し替えたり削ったりした場合は、新しい素材一式でカメラを推定します。

抽出した `frames` や `native-frames` は作業用です。学習データと向きの準備が終わると片付けます。保存するのはカメラ推定、照合データベース、レンズ補正済みの `dataset`、PLYと実行記録です。撮り足しや別解像度で元の画像が必要になれば、同じ元動画・写真から再生成します。

カメラ推定を一から行う場合、動画内は10コマ先までを照合し、動画ごとの代表20枚と写真を相互照合します。200枚以上の新規データではグローバル推定を先に使います。最近の部屋素材では43,890組に絞った照合データから1,350枚を登録し、既存の照合データを使った校正とグローバル推定に約7分38秒かかりました。照合時間は別です。2026-11-17の撮り足しでは1,393枚の既存位置を引き継ぎ、合計1,839枚を登録しました。

学習後の仕上げで、復元したカメラの上向きと部屋の消失点から求めた補正を `room.ply` 自体に適用します。推定できた床面は水平でZ=0になります。スプラットの位置・向き・視点に応じた色も一緒に回転し、Blenderでは前方+Y・上方+Zで直接読み込めます。各回の `alignment.json` に推定方法と撮影座標からPLY座標への変換行列が入ります。

run.log に処理経過と完了までの概算、result.json に使用したカメラ推定と学習データの実行名・登録数・総ステップ・容量が出ます。高速版Brushは100ステップごとに進捗と現在の点数を伝えます。中間PLYも従来の間隔で保存します。PLYには10 GBの上限があります。原寸PNGとレンズ補正済み画像は別に作業用ディスクを使います。

長辺1,280 px・5 fps・73,560ステップ・150万スプラットでは、作成済みの学習データを再利用し、学習からPLY出力まで1時間34分35秒かかりました。その学習データを撮り足しから準備した回は27分41秒で学習工程に到達しました。元の動画・写真140ファイルからの再抽出は4分40秒で、2,169枚のPNGが保存されていた画像とバイト単位で一致しました。[学習結果](runs/20261117-183156-823-23380/result.json) · [前処理ログ](runs/20261117-180354-673-35928/run.log)

### ガウシアン学習の高速化

`Train-Room.cmd` の既定の学習方式はBrush 0.3.0を基にした高速版です。SSIMと勾配をGPUの専用カーネルで計算し、位置・回転・色などを並行して読み出してPLYに直接書きます。Faster-GSは同じカメラ推定と画像を再利用でき、PowerShellからは `-Trainer faster-gs` または `-Trainer faster-gs-optimized` で選択できます。 [Faster-GSのセットアップ](apps/faster-gs/README.md)

2026-11-19の入力では、長辺1,280 px・6,000ステップ・上限150万点で、高速版Brushは3分54秒、高速版Faster-GSは2分30秒でした。未学習24視点の平均PSNRはそれぞれ21.36 dBと17.65 dBでした。 [Faster-GSとの比較](capture-review/faster-gs-v001/README.md)

前回と同じ1,839枚・長辺1,280 px・総ステップ設定73,560・上限150万点で比較しました。最初の1,000ステップと中間PLYは38.9秒から20.2秒、150万点からの1,000ステップと2回のPLY保存は77.7秒から53.2秒になりました。計測は各1,000ステップの区間です。[測定記録](capture-review/training-speed-v001/README.md)

学習設定はPowerShellからも指定できます。以前のカメラ推定を明示する場合は、同じ素材とfpsを指定し、推定を保存した実行フォルダ名を `-ReuseRun` に渡します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\vibe\house-gaussian-splat\Train-Room.ps1' -MaxEdge 1920 -VideoFps 5 -MaxSplats 300000 -AverageSteps 20
```
## 学習ステップの画質を比較する

評価用には、学習データのカメラ推定で未登録だった写真と動画フレームを優先します。その画像だけ既存の点群に対して位置を求め直し、共通点の数・画面内での広がり・再投影誤差を確認できたものを使います。学習用から抜き出した代表視点も別の系列で記録します。

次にグラフを作るときは、同じ評価視点と解像度で途中のモデルを描画します。画像1枚あたりの平均ステップ数と経過時間に対して、評価用・学習用それぞれのPSNRやSSIMを記録します。床や家具を同じ範囲で拡大した画像も併せて比較できます。

今回の `held_out_views` は位置を確認できた評価用、`training_views` は学習用の代表視点です。位置を確認した9枚と暫定の9枚の元画像を、評価フォルダの `images` に相対名のまま保存しています。[evaluation-views.json](runs/20261117-180354-673-35928/evaluation/evaluation-views.json)

## ソフトの役割

- FFmpeg 9.0.2 で動画からPNGを抜き、表示回転を適用します。HEIC写真は同梱のpillow-heifで原画素を読みます。[Windows版配布元](https://www.gyan.dev/ffmpeg/builds/)
- COLMAP 4.2.1（CUDA版）でカメラ位置・向きと疎な点群を求めます。[COLMAPの配布元](https://github.com/colmap/colmap/releases/tag/4.2.1)
- 高速版BrushまたはFaster-GSでGPU学習し、ガウススプラットをPLYに書き出します。 [Brushの高速化差分](apps/brush-0.3.0-training/README.md) · [Faster-GS](apps/faster-gs/README.md)
- ポータブル版 Blender 5.3.0 でPLYを開き、表示とレンダリングを行います。既存の家は Blender 5.2.1 の実行ファイルを通常起動と壁の検査から参照しているため、そちらも引き続き使います。[Blender 5.3.0の配布元](https://download.blender.org/release/Blender5.3/)

検証では元の2本に加え、短く切り出した動画とJPEGを混ぜた入力で、フレーム抽出からPLY書き出しまで通しました。処理はこのPC内で実行しています。
